## 用户意图
> 想把当前 Tauri 桌面应用迁移成"在线网页版"，让用户访问一个网址就能直接使用。
> 用户表示自己有服务器。

## 关键现实约束（要先和用户对齐）
当前桌面版有三件浏览器**搬不动**的能力，迁移方案必须先决定怎么处理：

1. **Agent CLI 子进程**：`claude` / `codex` / `opencode` 是命令行程序，桌面版本地起子进程。浏览器无法启动子进程 → 必须搬到服务器。
2. **本地文件系统**：用户当前能选项目目录、agent 直接改本地代码、跑 git。浏览器只能"上传文件"，不能读写完整目录树 → 服务器需提供工作目录和 git 能力。
3. **桌面 OS 集成**：托盘、桌宠浮窗、窗口拖拽等都是 OS 概念，网页版没有。

## 已经讨论过的形态选项

| 形态 | 描述 | 大致工作量 | 服务器成本 |
|---|---|---|---|
| A. 轻量 demo（聊天 + 桌宠） | 进网站只能聊天 + 看桌宠，不能操作代码项目 | 1-2 周 | 极低 |
| B. 完整云端 IDE | 用户登录 → 服务器起容器 → agent / git / 文件全在云上 | 3-6 个月（单人） | 高（每活跃用户长期占用容器） |
| C. 控制面板 | 桌面版仍要装，网页是远程入口（局域网模式的扩展版） | 1-2 个月 | 中（需要中继 / 隧道） |

## 还没决定的问题
- 形态选 A / B / C 还是其它
- 部署模式：单租户（用户自部署）vs 多租户（你运营）
- 用户身份：匿名 / 仅昵称 / 正式登录
- LLM API key 由谁提供（用户自填 vs 你的服务器代付）
- agent CLI 网页版是否保留
